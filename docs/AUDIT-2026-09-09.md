## High-priority findings

P1 means fix before the redesigned hosted experience launches. P2 means a material correctness, product or maintainability gap to address in the associated workstream.

### A01 · P1 · Upstream WebSocket writes are not serialized

The browser-directed connection has a mutex, but section transitions, received tool calls and candidate audio send to the Gemini session from different goroutines. The installed genai v1.66.0 `Session.send` calls Gorilla `WriteMessage` without a writer mutex. Concurrent audio and section/tool activity can therefore trigger a concurrent-writer panic. The existing race suite does not cover that upstream interaction.

Evidence: [relay.go](../api/internal/live/relay.go), lines 460, 550 and 578; installed `google.golang.org/genai@v1.66.0/live.go`, lines 274–300. Add a single upstream writer/queue, shutdown coordination and a simulated provider test exercising concurrent audio, transitions and tool responses.

### A02 · P1 · Audio interruption and microphone disposal fail

An `interrupted` event cancels browser speech synthesis but does not stop queued native PCM audio sources. The avatar can remain in speaking state. Separately, `startMic` lacks the disposal check after awaiting `getUserMedia`, so a delayed permission resolution attaches capture to an ended session.

Evidence: [live.ts](../web/lib/live.ts), lines 220, 347 and 365–415. The temporary harness reported zero stopped audio sources on interruption and zero stopped tracks after the late-permission case. Retain/cancel all sources and recheck lifecycle after asynchronous media setup.

### A03 · P1 · Provider failure can look connected and retry indefinitely

The relay emits `type: error` on setup/model failures; the client has no corresponding message handler. It resets retry count and reports connected at raw WebSocket open, before model readiness. A provider rejection after every socket open defeats the retry limit.

Evidence: [relay.go](../api/internal/live/relay.go), lines 257, 283 and 327; [live.ts](../web/lib/live.ts), lines 140 and 182–236. Introduce ready/error events, typed retryability and explicit terminal failure UI.

### A04 · P1 · Quotas are bypassable and charge failed starts

The configured default is two interviews/day. Counting today's sessions ignores database errors, then creates the session outside the count transaction. Parallel starts can pass together. Created sessions count even when devices/provider fail. The live handler accepts any owned session, including completed ones, and marks it active again. No distributed active-session lease prevents duplicate sockets or cost.

Evidence: [config.go](../api/internal/config/config.go), lines 74–78; [interview.go](../api/internal/interview/interview.go), lines 144–156; [sessions.go](../api/internal/store/sessions.go), lines 40–45; [relay.go](../api/internal/live/relay.go), lines 177–208. Replace with atomic reservations/usage ledger, guarded state transitions and account/session leases.

### A05 · P1 · Admin permissions trust an unverified signup email

Admin-email defaults are public in config. Registration accepts the supplied email without ownership verification, and feedback administration/unlimited quota trust that email. An unclaimed configured administrative email could be registered to gain those privileges. Exploitability depends on production configuration and whether those accounts already exist; this was not tested against production.

Evidence: [config.go](../api/internal/config/config.go), line 74; [auth.go](../api/internal/auth/auth.go), lines 127–158; [feedback.go](../api/internal/feedback/feedback.go), line 85; [interview.go](../api/internal/interview/interview.go), lines 64–69. Use explicit persisted roles and a controlled bootstrap, with verified hosted identities.

### A06 · P1 · Finish can miss the last answer or report success without a saved report

The client closes the socket and immediately posts finish. The relay drains asynchronous transcript writes during teardown, so scoring may read first. Finish also ignores transcript/workspace read errors, report persistence errors and status-update failures, then reports success. Repeated/concurrent finish calls can invoke paid scoring again.

Evidence: [room page](../web/app/interview/page.tsx), lines 159–177; [relay.go](../api/internal/live/relay.go), lines 362 and 627–634; [interview.go](../api/internal/interview/interview.go), around line 250; [app.go](../api/cmd/mockinterview/app.go), line 139. Seal acknowledged input before enqueueing one durable job, and commit report/status together.

### A07 · P1 · Recovery resets time, chronology and work

Each live connection timestamps turns from a new zero, but the database orders all turns by `ts_ms`. New turns can appear among the opening dialogue. Section timers restart; browser refresh resets the countdown. History resume drops the chosen duration. The backend's 30-minute live timeout conflicts with UI choices up to 60 minutes.

Only the transcript is reloaded into the room. Workspace has no saved-state input; notes initialize empty and emit on mount. Whiteboards store labels/counts rather than the editable scene. Debounced saves have no flush before finish.

Evidence: [relay.go](../api/internal/live/relay.go), lines 274, 351, 426 and 547; [sessions.go](../api/internal/store/sessions.go), line 155; [room page](../web/app/interview/page.tsx), lines 67–74, 116–119 and 277; [history page](../web/app/results/page.tsx), line 61; [Workspace.tsx](../web/components/studio/Workspace.tsx), lines 17–32, 65–80 and 113–118. Persist canonical clock/stage/sequence/full artifacts and restore before writing.

Current source **does** enable sliding-window context compression at relay line 312. It does **not** configure provider session resumption. Compression and reconnect recovery must both be addressed; the older notes overstate seamless recovery. Google documents these as separate mechanisms. [Gemini session management](https://ai.google.dev/gemini-api/docs/live-api/session-management).

## Realism, assessment and product gaps

### A08 · P2 · Authored interview instructions and facts are lost

Built-in domain guidance replaces `interviewer_notes`; the notes only apply to unknown domains, and every current domain is known. `extractProbes` flattens selected strings, drops triggers, ignores coding follow-ups and scenario/model facts, and keeps at most 12 probes. This prevents a reliable fact-reveal policy and defeats substantial authoring work.

Evidence: [director.go](../api/internal/live/director.go), lines 293–299 and 364–394; [consulting scenario](../api/data/corpus/case-profitability.json), line 59; [MMI scenario](../api/data/corpus/mmi-ethical-dilemma.json), line 118. Compose domain and scenario guidance; preserve facts, triggers and reveal rules as structured runtime input.

### A09 · P2 · Generic pacing and temperament conflict with realistic formats

Every session of at least six minutes reserves 3.5 minutes for intro and 2.5 for wrap-up. An eight-minute MMI gets two minutes of scenario time, or one if a stored resume adds another section. Difficulty is fixed question metadata; target level/challenge are absent from user configuration and evaluation context. A supportive persona offers hints while global instructions forbid them. The introduction uses a voice label instead of the selected face's name and includes an instruction to deny being AI.

Evidence: [relay.go](../api/internal/live/relay.go), lines 653–680; [director.go](../api/internal/live/director.go), lines 155–173, 237–254 and 352; [personalities.go](../api/internal/persona/personalities.go), lines 21–22; [config data](../api/internal/store/config.go), lines 9–19; [scoring.go](../api/internal/scoring/scoring.go), lines 96–108. Make pacing, assistance and expectations explicit per format/level and use one transparent interviewer identity.

### A10 · P2 · Scoring may lose late evidence and accepts inconsistent rubrics

The scorer truncates to the first 16,000 transcript bytes and 8,000 workspace bytes, potentially excluding the most important later work and corrections. Model-returned dimensions are not checked for an exact, unique match to the rubric; model-provided positive weights are accepted. Pack readiness divides a 0–4 overall score by five, so a perfect score becomes 80%.

Evidence: [scoring.go](../api/internal/scoring/scoring.go), lines 107 and 175–209; [pack service](../api/internal/pack/service.go), lines 186–190. Evaluate full bounded evidence segments, enforce the canonical rubric and correct scale normalization.

### A11 · P2 · Broad corpus coverage does not equal broad format depth

Pooled packs always select the alphabetically first matching question and do not exclude earlier attempts. Sales and UX one-offs are categorized under product; HR/teaching appear as shared behavioral scenarios. The contributor example omits mandatory `areas`. Documentation requests 6–12 rubric dimensions while validation permits one and current content includes five/thirteen. Reference JSON can lack the facts a specific format needs.

Evidence: [pack.go](../api/internal/pack/pack.go), lines 133–159; [sales scenario](../api/data/corpus/sales-discovery.json), line 5; [portfolio scenario](../api/data/corpus/ux-portfolio-walkthrough.json), line 5; [CORPUS.md](CORPUS.md), line 19; [corpus.go](../api/internal/corpus/corpus.go), lines 88 and 139. Separate format/scenario/pack schemas, rotate questions, calibrate levels and supply valid scaffolded examples.

### A12 · P2 · Own-key support needs session-level provider selection

The reasoning client is process-wide, profile/session config has no credential/provider contract, and native voice always uses the deployment Gemini key. A form alone would not make all providers usable for interviews.

Evidence: [main.go](../api/cmd/mockinterview/main.go), line 68; [new.go](../api/internal/llm/new.go), line 12; [config data](../api/internal/store/config.go), line 9; [relay.go](../api/internal/live/relay.go), line 280. Add isolated credential handling, per-session provider resolution and mode capability checks, including scoring and speech costs.

### A13 · P2 · UI complexity obscures the task and hides failures

The path is sign-in → mandatory professions → dashboard → catalog → long interviewer setup → room. The dashboard emphasizes streaks/achievements and cross-format averages. The room lacks device preflight, microphone mute/camera toggle and a persistent task brief. Camera self-view requests access even when analysis is off. Typed answers can appear sent while disconnected. Many data failures appear empty or keep loading; report loading lacks a durable processing/retry state. Browser fallback recognition and speech are English-oriented despite language selection.

Evidence: [AppShell.tsx](../web/components/AppShell.tsx), onboarding gate; [setup page](../web/app/setup/page.tsx), lines 173–199; [room page](../web/app/interview/page.tsx), lines 59–136 and 251–281; [live.ts](../web/lib/live.ts), lines 78–84, 248 and 317–332; [report page](../web/app/report/page.tsx), lines 39–49. Redesign around a short setup, explicit device/provider readiness and recoverable interview states.

### A14 · P2 · History and feedback exist, but are incomplete

History lists 50 attempts without pagination and presents all non-complete attempts as resumable. Feedback already stores ratings/messages/context and supports admin reads, but there is no report-time interviewer/product feedback split or triage workflow. In-room context copies the last 12 captions and configuration; future BYOK fields must never enter that payload. Arbitrary context needs allowlisting/redaction and optional transcript sharing.

Evidence: [interview.go](../api/internal/interview/interview.go), line 75; [history page](../web/app/results/page.tsx), lines 45–61; [feedback.go](../api/internal/feedback/feedback.go), line 40; [FeedbackWidget.tsx](../web/components/FeedbackWidget.tsx), lines 47–61 and 110–139; [room page](../web/app/interview/page.tsx), line 198. Account deletion currently cascades to feedback as well as practice records; preserve and document those semantics.

The raw-behavior purge function is explicitly not scheduled, despite approximately 30-day retention claims. Evidence: [behavior.go](../api/internal/store/behavior.go), lines 16–18; [TDD.md](TDD.md), line 206. Implement and observe the retention job.

### A15 · P2 · Avatar quality is limited by animation timing and presentation

There is already a bundled glTF/morph-target pipeline. Mouth values update when PCM packets arrive, although playback is scheduled later; its amplitude/brightness approximation is not phoneme alignment. Room state does not consistently connect configured demeanor to the avatar. Reduced motion and low-power/static fallback need explicit coverage.

Evidence: [live.ts](../web/lib/live.ts), lines 408–415; [GltfAvatar.tsx](../web/components/studio/GltfAvatar.tsx), lines 128–175; [room page](../web/app/interview/page.tsx), lines 89 and 108. Improve assets, playback-driven animation and professional framing before adding a paid streamed-video dependency.

### A16 · P2 · Local and deployment guidance is not reproducible enough

README omits frontend dependency installation. `make up` uses a fixed two-second wait; `make seed` calls an undefined flag; `make test` runs only Go despite broader documentation. CI tolerates lock drift with `npm install` and builds frontend mock mode. Compose starts only Postgres, not the whole self-hosted app.

Evidence: [README.md](../README.md), line 24; [Makefile](../Makefile), lines 14, 28, 35 and 46; [main.go](../api/cmd/mockinterview/main.go), line 31; [CI](../.github/workflows/ci.yml), line 45; [docker-compose.yml](../docker-compose.yml).

Deployment uses a mutable image tag, immediately changes serving traffic, passes secrets as environment values, and has stale site/domain/health-check descriptions. The exact verified resources and safer release sequence are documented in [DEPLOYMENT-UPDATE-PLAN.md](DEPLOYMENT-UPDATE-PLAN.md).

## What the passing tests establish

The existing suite is a useful base for deterministic handlers, corpus shape and frontend data/mock helpers. It is not evidence that PostgreSQL failures, real-provider concurrency, browser permissions, interrupted playback, state recovery or realistic dialogue are correct. Expand around the actual failure modes above and validate the reference interviews before advertising the redesigned experience as dependable.
